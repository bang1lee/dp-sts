# 기존 제작 시스템의 선택형 엔진 확장

2026-11-02. 사용자의 결정: 지금 시스템을 유지하면서 확장하고 보완한다. 잘못 보낸 Strudel → Hydra 전환 요청은 실행 근거로 삼지 않는다. 저장소에 있는 다른 실험과 산출물은 보존한다.

## 무엇을 더했는가

Nx 공식 `@nx/js:library` 생성기로 `packages/engine-bridge`를 추가했다. 기존 Strudel·WebGL·OpenCV 제작 경로 옆에, 선택한 WAV와 공통 시간축·푸리에 계수를 cables 또는 TouchDesigner로 넘길 수 있는 연결 계층을 마련했다. 의존성·환경 관리는 기존 pnpm/uv를 사용한다.

| --------------------- | -------------------------- | ------------------------------------------------------------- |
| 공통 묶음 내보내기    | 실행 검증                  | 기존 WAV의 350–380초, 30초·48 kHz·스테레오, 720개 제어 프레임 |

cables 위치: `/Users/light_one/Applications/cables.app`. 다운로드한 공식 설치 파일은 `runs/engine-installers/cables-arm64.dmg`에 보관했다. 기존 앱을 덮어쓰지 않는 조건으로 설치했다.

추가 UI 검사용 `expect-cli`도 실행했지만 기본 Claude provider의 인증 누락(`AcpProviderUnauthenticatedError`)으로 검사 시작 전에 종료되었다. 따라서 브라우저 자동 검수 통과로 기록하지 않는다. cables 환영 화면·버전 표시는 실제 네이티브 UI에서 별도로 확인했다.

## 작업 방식

컨셉마다 오디오·장면·피드백 순서를 다르게 선택할 수 있다. 공통으로 지키는 것은 비교할 음원, 구간, 제어값의 출처를 명시하는 것이다. 음악부터 시작해도 되고 정지 이미지나 공간 실험부터 시작해도 된다.

1. 비교할 WAV와 구간을 명시해 새 폴더로 묶음을 만든다.
2. 사용할 엔진에서 실제 오디오 재생 시간을 입력하고 점군·제어값을 원하는 표현에 연결한다.
3. 짧은 구간으로 윤슬의 밀도, 반짝임 빈도, 수중 시점, 긴 디졸브를 검토한다.
4. 표현 방향이 정해지면 해당 장면의 장시간 렌더와 동기화·영상 분석을 검증한다.

현재 Moonwater 곡선은 실험용 프리셋이며 작품마다 바꿀 수 있다. 측정된 음량과 저작된 서사 곡선을 구분한다. 모든 오브제의 푸리에 정렬이나 10분 네이티브 작품 완성을 이번 코드의 성과로 간주하지 않는다.

## 두 방향의 샘플 사용

[실시간 비교 화면](http://localhost:4200/comparison.html)은 같은 30초 음원을 사용하는 두 브라우저 방향 시안이다. 실제 cables·TouchDesigner 렌더를 스트리밍한 화면은 아니다. 재생·시간 이동과 밀도·반짝임·움직임·정렬을 조절하고 설정을 저장할 수 있다.

실제 엔진 파일과 검수 결과는 [네이티브 샘플 안내](native-sample.md)에 모았다. TouchDesigner는 설치된 앱에서 직접 실행했으며 기존 다운로드 실패 기록은 설치 여부의 근거가 아니었다. cables는 앱 재시작 후 실제 패치를 불러와 렌더와 사용자 조절을 확인했다. 두 샘플은 엔진 연결 및 조작 실험이며, 수중 윤슬의 최종 미감이나 10분 작품의 완성 검수는 별도다.

사용 명령과 어댑터 입력·출력은 [engine-bridge 안내](../packages/engine-bridge/README.md), 대안의 근거와 출처는 [TouchDesigner·cables 조사](touchdesigner-cables-research.md)에 정리했다.
