# 작업대 독립 검수

검수 기준일: 2026-11-03. 담당: `workbench_critic`. 수정 소유권은 이 문서에 한정한다. 구현자의 자체 확인, 독립 검수, 사용자의 미감 승인은 별개다.

## 목표와 현재 판정

사용자가 설치된 도구의 역할을 이해하고 한국어 작업대에서 소리와 영상의 관계를 유연하게 설계하며, 새 음악과 그 음악에 동기화된 영상을 실제로 내보낼 수 있어야 한다. 공간·깊이, 입자 밀도, 블룸, 프랙탈 연속성, 미시·거시 관점, 실제 Mandelbulb의 조작이 결과로 관찰되어야 한다.

최종 판정: **30초 브라우저 탐색·생성·실시간 내보내기 프로토타입으로 수용**. v2의 실제 생성 음악, 동기 영상, 조절기, 기본 시각 방향 및 UI 조작 근거를 검토했다. 정밀 오프라인 렌더나 최종 작품 승인으로 확대하지 않는다. 아래 마지막 절에 최종 근거와 제한을 기록했다.

초기에는 미검증/구현 진행 중이었다. 기존 `comparison.html`은 같은 WAV와 제어 곡선을 사용하는 Canvas 방향 비교다. 실제 cables 또는 TouchDesigner 렌더도, Mandelbulb도, 새 음악 제작 화면도 아니다. 기존 화면과 네이티브 검수 기록을 새 작업대의 완료 근거로 전용하지 않았다.

이번 검수 범위는 **30초 실제 출력이 검증된 프로토타입**이다. UI가 제공하는 5–120초 제한을 명시하고, 검증 범위를 정직하게 표시하면 이 단계의 수용 대상이 된다. 기존 장시간 제작 의도를 이유로 이번 단계에 새 10분 렌더를 강제하지 않는다.

읽은 지침: 프로젝트 `AGENTS.md`, `agent-system-engineering`과 공통 작업 계약, `loop-engineering`, 프로젝트 로컬 `nx-workspace`. 사용자 요청에 따라 실패 근거를 기존 구현 담당에게 돌려 재검수하며 임의로 기준을 낮추지 않는다.

## 구현 전 주요 함정

1. 재생 시간과 녹화 시간을 별도 시계로 굴리면 정지·탐색·초기 오디오 지연에서 어긋날 수 있다. 출력 프레임은 같은 오디오 시간 또는 같은 고정 프레임 인덱스를 기준으로 해야 한다.
2. 설정 변경 뒤 오래된 오디오 마스터나 녹화 중 바뀐 설정을 재사용하면 현재 조작 결과와 파일이 다르다. 내보내기 시작 시점의 스냅샷과 준비 상태를 명시해야 한다.
3. WebGL bloom, 입자 밀도, fractal continuity는 서로 다른 의미를 가진다. 하나의 밝기나 노이즈 값에 여러 명칭을 붙이는 것으로 통과하지 않는다.
4. 브라우저의 MediaRecorder는 현재 환경에서 실제 지원한 형식으로 제공해야 한다. WebM을 MP4로 표기하거나 프레임 정확한 오프라인 렌더로 부르면 실패다.
5. 전체 예술적 완성은 객관적 자동 검사만으로 확정할 수 없다. 직접 본 이미지의 장단점과 실제 청취 여부를 구분해서 기록한다.

## 기본 장면의 미술 검수

기본 달빛 장면은 빛점이 화면을 채운다는 이유만으로 통과하지 않는다. 실제 프레임에서 가까운 반짝임과 먼 빛의 크기·명암 차이, 공간의 겹침, 수면을 암시하는 방향성, 빛 번짐 뒤에도 남는 형태를 확인한다. 미시/거시 조작과 깊이 조작이 다른 경험을 주는지도 본다. 낮은 대비의 어두운 화면, 동일 크기의 균등한 점 분포, 과도한 블룸으로 사라진 구조는 수정 대상이다. 이 기준은 사용자의 최종 취향 승인을 대신하지 않는다.

초기 UI/부분 엔진 관찰: 음악 여백 값은 현재 세 구간으로만 패턴을 바꾼다. 연속 슬라이더를 유지한다면 그 단계성을 설명하거나 실제 연속 반응을 구현해야 한다. 모드마다 의미가 달라지는 밀도·연결·깊이는 문구도 맞춰야 한다. 현재 작업대가 Strudel을 사용한다면 도구 안내에도 현재 생성 경로로 표시해야 한다. 엔진 작성 중의 관찰이므로 최종 결함 판정은 완성 소스를 다시 읽은 뒤 한다.

## 증거 요청과 재개

총괄에게 실제 데스크톱/모바일 화면, 조절기 비교 이미지, 다운로드한 WAV·영상 경로, 실행한 검사 결과, 재생·탐색·초기화의 실제 조작 근거를 요청했다. CUA 조작은 총괄만 수행한다. 이 검수자는 최종 소스와 전달된 실제 이미지·파일을 독립적으로 검사한다.

최종 소스와 산출물 도착 후 구현/기능/미감/파일 검증을 각각 통과·실패·미검증으로 갱신한다. 아직 최종 통과나 사용자 만족을 선언하지 않았다.

## 1차 실제 산출물 검수

입력: `runs/workbench-review-v01/moonwater-default.png`, `mandelbulb-default.png`, `fractal-default.png`, `music.wav`. 세 이미지는 총괄이 실제 UI에서 같은 10초 위치로 저장했다. 검수자는 세 PNG를 직접 열어 보았고 WAV를 Python `wave`/PCM 샘플 검사로 읽었다. 검수 시점 엔진 210줄, UI 135줄과 `docs/workbench-engine-api.md`를 읽었다.

판정: **수정 필요**. 음악 파일의 기술적 유효성과 실제 Mandelbulb 구현은 확인했다. 기본 장면의 미술 방향과 일부 조절 의미는 아직 기준에 못 미친다. 동기 영상은 아직 전달되지 않아 미검증이다.

### 반드시 수정할 조작 결함

1. **Julia 움직임 0에서도 형태가 움직인다.** `c`의 `sin(time*.027)`, `cos(time*.033)`에는 `motion`이 곱해지지 않는다. 정지 가능한 시간 변수로 통일하고, 반응 0·움직임 0에서 서로 다른 시간의 프레임이 같은지 확인한다.
2. **달빛의 공간 깊이는 설명과 다르다.** 현재 `depth`는 x 변형의 진폭만 바꾼다. 층 사이 거리·투영·입자 크기·명암·속도 차를 조절해 실제 전후 관계를 바꾸거나, 현재 기능에 맞게 이름을 바꿔야 한다. 사용자가 공간 깊이를 요청했으므로 실제 깊이 구현이 우선이다.
3. **Julia 무늬 폭 설명이 역방향이다.** `exp(-trap*(14+20*density))`는 높은 값에서 띠를 좁힌다. UI의 '얇게 ↔ 넓게'를 구현 방향에 맞춘다.
4. **Mandelbulb 빛 번짐이 실제 번짐이 아니다.** 현재 `bloom`은 표면 rim 밝기만 올린다. 외곽 광 확산을 구현하거나 해당 모드에서 '가장자리 밝기'처럼 실제 의미를 표시한다. 같은 화면의 별도 가장자리 빛 조절기와 역할 중복도 정리한다.

### 미술 개선 방향

- 달빛: 빛을 전면적으로 밝히기보다 수면의 원근과 몇 군데의 반사 경로를 만든다. 가까운 은색의 가로로 긴 반짝임, 먼 곳의 작은 점, 어두운 물결의 가림, 서로 다른 속도의 층을 함께 사용한다. 현재의 어두운 여백은 유지하되 주요 빛의 크기와 명암 차이를 충분히 만든다.
- Mandelbulb: 세부 구조는 풍부하지만 기본 화면이 위아래 외곽을 자르고 중간 밝기가 눌려 있다. 기본 관찰 크기에서 전체 실루엣을 먼저 인지할 수 있게 하고, 확대하면 현재 세부가 드러나도록 한다. 한쪽 주광과 약한 가장자리 빛의 역할을 분리한다.
- Julia: 반복된 큰 구멍과 가는 경계는 매력적이다. 중심 경계의 국소 하이라이트를 올려 검은 배경에서 읽히도록 하되 모든 밴드를 똑같이 밝히지 않는다.
- 오디오 반응: 현재 RMS 0.032, 기본 반응 0.55라면 달빛의 전체 밝기 변화는 약 3.5%다. 작동은 하지만 사용자에게 거의 안 보일 수 있다. 상한을 둔 지각적 매핑을 적용하고, 조용한/큰 구간 × 반응 0/1 비교로 확인한다.

초기 지적 중 음악 여백은 3단계 슬라이더와 한국어 출력값으로 정리됐고, 모드별 이름과 Strudel 현재 역할도 추가됐다. 이 개선은 확인했으나 위 결함을 상쇄하지는 않는다.

## 1차 동기 영상 독립 검사

입력: 실제 UI로 생성한 `runs/workbench-review-v01/mandelbulb.webm`과 같은 `music.wav`. 분석: FFprobe 패킷 타임스탬프, FFmpeg 디코딩, NumPy/SciPy 오디오 상호상관, 저장 PNG와 영상 프레임의 정규화 픽셀 비교. 결과 파일: `runs/workbench-review-v01/export-analysis-v01.json`, `export-frame-{00,10,20,29}.png`.

- VP9 960×540 영상과 Opus 48 kHz 스테레오 음성이 실제 들어 있다. 비디오 911패킷, 마지막 비디오 PTS 30.629초, 오디오 패킷 끝 추정 30.674초다. WebM에 전체 길이 메타데이터가 없으므로 패킷으로 확인했다.
- WAV와 WebM에서 각각 12 kHz 모노 PCM을 디코드해 비교했다. 최적 상대 이동은 +56.5ms, 중첩 29.9435초의 상관계수는 **0.9997798**이다. 새로 만든 음악과 같은 내용의 음성이 출력됨을 강하게 뒷받침한다. 손실 압축이므로 바이트 동일성을 주장하지 않는다.
- 오디오 스트림 첫 PTS는 0.671초다. 오디오 상관 결과를 포함한 음악 시작은 컨테이너 시간 약 0.7275초다. 반면 미리보기 정확히 10초 PNG는 출력 시간 **10.700초** 프레임과 가장 잘 일치한다. 이는 공통 준비 구간 약 0.7초와, 표본 해상도 1/30초 범위에서 약 **27.5ms의 잔여 음영상 차이**를 뜻한다. 시작 지연 0.7초 전체를 음영상 불일치로 오판하지 않았다.
- 0·10·20·29초 디코드 이미지를 직접 확인했다. 검은 영상이나 정지 이미지가 아니며 입체 구조의 회전과 가림이 변한다.
- 프레임 간격 중앙값 34ms, 95백분위 50ms, 최대 256ms다. 실제 프레임 간격이 달라지는 실시간 녹화이며 정확한 30fps 오프라인 렌더는 아니다.
- 디코드 오디오는 30초지만 앞쪽 약 56.5ms의 패딩 때문에 WAV 끝 약 56.5ms는 정렬 중첩에서 빠진다. 끝 페이드가 있으나 샘플 전체 보존으로 표현하면 안 된다. 소스 종료 뒤 짧은 녹화 여유를 두는 개선을 권고했다.

판정: **30초 실시간 동기 영상 프로토타입의 기술적 출력은 조건부 통과**. 생성 음원, 변화하는 영상, 공통 타임라인이 실제 확인됐다. 공통 준비 구간·가변 프레임 간격·끝 패딩을 공개하고, 정확한 프레임 수·샘플 보존·120초 전체 성능을 주장하지 않는 범위다. 앞서 발견한 미술 및 조절기 결함은 계속 수정 대상이다. 엔진이 바뀌면 영향을 받는 화면과 실제 출력을 다시 검수한다.

## 최종 판정 — v2 프로토타입 수용

2026-11-03, 유일한 독립 판정 담당 `workbench_critic`/Astra. 사용자 결정에 따라 기존 증거를 재사용하고 수정 영향에 한해 재검사했다. **이번 30초 작업 프로토타입의 필수 수정은 완료되어 수용한다. 추가 구현 반복을 요구하지 않는다.** 사용자 미감 승인과 장시간·정밀 제작 성능은 별도다.

### 독립 검사자가 직접 확인한 최종 미디어

대상: `runs/workbench-review-v02/moonwater.webm`, `music.wav`. 재사용하지 않은 실제 v2 파일을 디코드·분석했다. 결과는 `export-analysis-v02.json`과 `export-frame-{00,10,20,29}.png`에 남겼다.

- VP9 960×540 비디오와 Opus 48 kHz 스테레오 음성이 들어 있다. 마지막 영상 PTS는 30.137초, 패킷 끝 추정은 30.138초다. 영상 663패킷, 프레임 간격 중앙값 35ms, 95백분위 107.9ms, 최대 410ms다.
- 원본 WAV는 완전한 30초다. 출력 음성과의 정렬 상관계수는 **0.9997798**이다. 새로 생성한 음악이 실제 영상 파일에 들어 있음을 확인했다.
- 오디오 첫 PTS 0.049초와 디코드 상대 이동 0.0565초를 합친 음악 시작은 약 0.1055초다. 미리보기 10초 이미지의 수면 영역과 가장 잘 맞는 영상은 컨테이너 시간 약 10.100초다. 공통 타임라인과 일치하지만, 느린 수면 변화로 가까운 후보들의 차이가 작으므로 이를 '정확히 5.5ms 동기 오차'라고 주장하지 않는다.
- 0·10·20·29초 이미지를 직접 보았다. 실제 달빛 수면의 곡선과 빛점이 변하며, 검은 프레임이나 정지 이미지 대체가 아니다.
- **끝 페이드 제한은 남아 있다.** 100ms 마지막 영상 유지 후에도 오디오 정렬 중첩은 29.9435초다. 원본 마지막 56.5ms의 RMS는 −64.4dBFS, peak는 0.0027466이다. 이번 탐색용 손실 압축 미리보기의 수용을 막지는 않지만, 모든 샘플 보존 또는 꼬리 잘림 해결로 보고해서는 안 된다. 완전한 음악 원본은 별도 WAV에 있다.

### 총괄의 실제 UI 관찰을 근거로 수용한 항목

아래는 이 검수자가 브라우저를 직접 조작한 결과가 아니라, 브라우저를 전담한 총괄이 전달한 실제 CUA 관찰이다.

- 녹화 취소 후 조절기가 복구되고 20초 위치가 유지됐다. 최종 30초 내보내기는 실제 완료됐다.

- 최종 변경은 불러온 설정과 현재 마스터가 같을 때의 안내 문구였다. Nx build/typecheck 통과가 보고됐다. Expect는 provider 인증 때문에 차단되었으며 통과로 취급하지 않는다.

### 수용 범위와 후속 기준

수용한 것은 한국어 작업대에서 5–120초를 설정할 수 있고, **실제로 검증한 30초 구간**에서 새 음악 생성·완전한 WAV 저장·시각 조절·동기 WebM 기록·레시피 왕복이 가능한 브라우저 프로토타입이다. 실제 Mandelbulb, Julia, 달빛 수면을 구분해서 구현했다. 별도 앱/분석의 계획 선택을 라이브 연결 완료로 부르지 않는다.

실시간 녹화의 프레임 간격 편차와 낮은 음량의 마지막 페이드 일부 누락은 알려진 제한이다. 고정 30fps, 샘플 단위 완전성, MP4 직접 출력, 120초 전 범위 성능, 5–60분 장시간 제작, 플랫폼 간 동일성은 이번 수용에 포함하지 않는다. 이런 정밀 제작이 다음 목표가 되면 해당 출력 경로의 새 완료 기준으로 검증한다. 이번 작업을 불필요하게 계속 반복하지 않는다.

## 확장 범위 최종 수용 — 음악 JSON과 도구·매핑 계획

사용자가 추가한 확장 요청만 다시 검수했다. **음악 JSON 내보내기, 도구 역할·연결 상태 안내, v2 작업 계획·매핑 저장과 v1 호환을 수용한다.** 이전 시각·음영상 검수를 다시 수행하지 않았다. 아래 WAV 동일성 검사와 소스 변경 범위가 기존 근거 재사용을 뒷받침한다.

### 직접 확인한 소스·파일

- `packages/audiovisual/src/audio/offline.ts`는 `superdough`에 전달하는 동일 `value`, `begin`, `durationSeconds`에서 이벤트를 복사한다. 두 번째 패턴 질의나 별도 음악 재생성이 없다. 현재 sine/triangle 패턴의 파라미터는 스칼라로 보존된다.
- `music-document.ts`의 변환은 초/MIDI 단위, schema/version, BPM/cps, seed, 섹션, 실제 음색별 트랙, 고유 음표 ID를 기록한다. seed는 원래 Strudel 패턴의 seed이며 다른 엔진에서 동일 음색을 보장하지 않는다. `velocity:null`, 이벤트 `sourceGain`, PCM 이후 `masterGain`을 구분해 세기를 임의의 MIDI velocity로 꾸미지 않는다.
- 새 생성을 시작하면 이전 문서가 비워지고, 완료된 실제 이벤트로만 문서를 만들며, `getMusicDocument()`는 복사본을 반환한다. 음악 변경의 dirty 판정에 WAV·음악 JSON·영상 버튼이 모두 연결되어 있다.
- 실제 UI 다운로드 `runs/workbench-review-v03/music.json`을 읽었다. 30초, BPM 60, cps 0.25, seed 42, sine/triangle 2트랙, 고유 ID의 48개 음표다. 트랙 참조, 시작 순서, 초 단위 시작/길이, source sound, null velocity 검사가 모두 통과했다. 첫 음표 A2=45, 각 트랙의 source gain 0.15/0.036, master gain 0.65다.
- v03의 실제 `music.wav`는 v02 WAV와 **바이트 동일**하다. SHA-256: `9b8500626d94ecd46f55a032faf929257f9be59780de323aaba807c70947be8a`. 48 kHz 스테레오 PCM16, 1,440,000 프레임이다. 생성 음악 보존을 확인했으므로 기존 영상·시각 검수는 그대로 유효하다.
- 계획만 바꾼 뒤 다운로드한 `music-after-plan.json`은 앞 문서와 바이트 및 JSON 값이 동일하다. 계획 변경이 실제 생성 음악을 바꾸지 않는다는 근거다.
- `workbench-workflow.ts`는 버전·열거값·수치 범위·최대 8개 매핑을 검사하고 새 객체를 반환한다. UI는 검증 후에만 값을 적용하며 256KB 제한도 둔다. 정의되지 않은 도구 이름을 실행 경로로 넘기지 않는다. 연결 계획 이벤트는 실제 엔진을 교체하거나 실행하지 않는다.
- 도구 안내는 현재 Strudel/WebGL 연결, TouchDesigner/cables 별도 설치 앱, 나머지 미연결 도구와 계획을 구분한다. 음악 JSON을 Tone.js·Sardine·악보 도구에서 이미 재생하거나 변환할 수 있다는 주장은 없다.

### 발견·수정한 결함과 실제 UI 근거

초기 확장 코드의 import는 소수값을 허용했지만 HTML range step이 반올림할 수 있었다. 특히 여백 0.35가 0.5가 되면 실제 패턴 구간이 바뀐다. UI 담당자가 `step="any"`로 수정했다. 검수자는 `fractional-roundtrip.json`에서 BPM 60.5, 길이 5.5초, 여백 0.35, 밀도 0.35700000000000004와 TouchDesigner/OpenCV 계획이 보존된 것을 확인했다. 마지막 차이는 통상적인 부동소수점 표현 범위다.

다음 실제 브라우저 조작은 총괄이 수행해 전달했다.

- v1 소수값 가져오기 후 v2 저장에서 '촘촘' 여백 구간까지 유지했다. Tone.js·Verovio·MediaPipe와 손 거리→음역 매핑을 저장하고, Python 예시로 바꾼 뒤 다시 불러와 복원했다. 검수자가 `workflow-recipe.json`의 해당 값을 확인했다.
- 잘못된 v1 BPM 999와 v2 도구 이름은 음악·화면·계획을 바꾸지 않고 거부했다.
- BPM 120으로 변경하면 WAV·음악 JSON·영상·재생이 비활성화됐다. 현재 마스터 설정으로 되돌리면 다시 활성화됐다.
- Tone.js·Verovio 계획을 선택해도 ready 상태와 현재 Strudel 실행 표시가 유지됐다. 계획 변화 전후 실제 음악 JSON 동일성은 독립 검사로도 확인했다.
- 1280×800 데스크톱에서 펼친 계획 선택기가 4열로 읽혔고 현재 실행 안내·미리보기·다운로드 줄이 보였다. 355px 좁은 화면에서 계획 편집을 사용할 수 있었고 clientWidth와 scrollWidth가 모두 355px였다. 최종 빌드 이후 새 콘솔 오류는 관찰되지 않았다. 편집 도중 이전 HMR 빌드의 `updateRoute` 오류 2건은 남아 있었으나 최종 코드 오류와 구분했다.
- 담당자 보고: 음악 문서 순수 테스트 6건, Nx audiovisual test/typecheck 및 UI build/typecheck 통과. Expect 인증 차단은 계속 미실행으로 유지하며 통과로 부르지 않는다.

확장 수용은 **현재 음악을 설명하는 실제 이벤트 JSON과 향후 연결 계획**에 한정한다. 음악 JSON의 음표 편집·재생 왕복, Verovio 악보 변환, 카메라/MediaPipe 입력, 계획 매핑 실행, 외부 엔진 설치·연결은 이번 구현에 포함되지 않는다. 추가 차단 결함이 없으므로 변경 범위 검수를 종료한다.

Verovio 관련 제한은 이 작업실의 공통 음악 JSON→악보 형식 어댑터가 미구현이라는 뜻이다. Verovio 자체에 변환 기능이 전혀 없다는 뜻으로 확대하지 않는다.
