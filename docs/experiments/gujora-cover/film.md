# Gujora / Yundol · 180초 선의 바다

사용자 요청: “이걸로 3분짜리 만들어줘.” 바로 앞의 구조라·윤돌섬 커버를 입력으로 삼는다. 새로운 풍경으로 교체하지 않는다.

## 현재 연출 선택

1080×1080 정사각형, 24fps, 180초. 검은 여백과 비대칭 섬의 흰 선을 유지한다. 사진으로 지형을 재구축하는 영상이 아니라 완성된 커버 이미지의 영역별 좌표를 움직이는 이미지 기반 모션 작품이다.

검토한 두 방향은 전체 이미지의 느린 줌과 영역별 파동이다. 사용자 요청 및 앞선 유기적 선의 디렉션에 따라 영역별 파동을 선택한다. 이는 사용자가 별도로 고른 안이 아니라 위임된 제작 범위 안의 연출 판단이다.

- 0–45초: 고요한 형상에서 작은 물결이 생긴다.
- 45–135초: 해안 쪽 파동이 커지고 섬은 상대적으로 안정된 중심을 이룬다.
- 135–180초: 파동이 가라앉으며 커버의 형태로 돌아간다.

전체 화면을 밝게 점멸시키지 않는다. 글자·새로운 오브제·컬러를 추가하지 않는다. 섬과 해안의 연결, 선의 간격, 검은 여백을 실제 표본으로 확인한다.

## 입력과 음악

- 커버: `runs/dp-sts-gujora-cover-v01/dp-sts-gujora-yundol-cover.png`
- 음악: 기존 `bloom-master.wav`의 0–180초 구간. 앞선 Canopy Melt용 180초 발췌 WAV와 실제 주파수 분석을 재사용한다. 신규 작곡이라고 표현하지 않는다.
- 출력 작업 폴더: `runs/dp-sts-gujora-film-v01/`

Terra 6.1 ultra가 영상 코드를 구현하고 Astra가 실제 출력의 형상 유지와 세부 밀도를 검토한다. 실제 검수 이미지는 사용자에게 보여준다. 전체 디코딩 검사와 표본 시각 비평, 직접 청취는 구분한다.

실제 확인: 영상·음원·컨테이너 각각 180.000초, 1080×1080, 24fps, 4,320프레임, 48kHz 스테레오. 전체 디코딩 오류 0, 비정상 오디오 샘플 0, 풀스케일 이상 샘플 0. 입력 커버·WAV·제어 데이터와 렌더 기록의 해시 일치, 동결된 구현 소스 해시 일치. 방향 보정 검사에서 원본과 같은 좌우·상하 방향을 확인했다.

실제 렌더는 약 270초가 걸렸다. 초기 8초 미리보기의 영상 생성 후 라이브러리 버전 정보를 기록하는 단계에서 오류가 났고, 조회를 렌더 전으로 옮기고 경로를 수정했다. 별도 v02 미리보기와 최종 본편은 정상 완료됐다. 이전 미리보기는 보존했다.

Astra가 최종 MP4의 15·45·75·105·135·165초 및 90초 포스터를 실제로 확인해 시각 표본을 수용했다. 이 검수는 3분 연속 재생이나 음악의 직접 청취 판정이 아니다. 움직임은 원래 커버를 존중한 미세한 파동이며 큰 카메라 이동이나 완전한 3D 재구성이 아니다.

재실행: `pnpm nx run media:gujora-film -- --out=runs/새폴더` (기본 입력 폴더 재사용). 검증: 입력 자료가 함께 있는 기본 작업 폴더에 대해 `pnpm nx run media:gujora-verify`. 기존 영상·검사 출력은 명시적 새 경로나 검증 도구의 overwrite 옵션 없이 덮어쓰지 않는다.
