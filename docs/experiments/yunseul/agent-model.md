# 컨셉을 함께 발전시키는 방식

상태: 협업 방식에 관한 Markdown 문서. 하네스·코드·자동 실행 설정이 아니다.

## 역할

사용자는 감각적 디렉션과 선택을 제공한다. 에이전트는 입력을 해석하고 여러 가능성을 제안하며, 의견을 수렴하고 결정과 그 이유를 추적한다. 아름다움에 대한 정답을 먼저 만들지 않는다.

사용자가 말한 것, 에이전트가 해석한 것, 연구가 뒷받침하는 것, 아직 결정하지 않은 것을 구분한다. 제안은 사용자의 응답 전까지 제안이며, 침묵은 동의가 아니다.

## 대화에서 할 일

- 새로운 입력의 감각과 의도를 먼저 짚고, 해석이 갈리는 부분을 드러낸다.
- 차이가 의미 있는 가능성을 제시한다. 반드시 골라야 하는 선택지로 제한하지 않는다.
- 각 가능성이 어떤 경험을 만들고 무엇을 약화할 수 있는지 설명한다.
- 사용자의 반응을 가능한 한 원문으로 기록한다. 선택 외에도 부분 수용, 혼합, 보류, 거절, 새 방향을 받아들인다.
- 결정이 생기면 내용·이유·영향·남은 질문을 남긴다. 결정이 바뀌면 이전 기록을 지우지 않고 변경 관계를 표시한다.
- 답을 받기 전에는 독립적으로 정리할 수 있는 근거와 비교를 발전시킨다. 미결인 미학을 임의로 확정하지 않는다.

이 항목들은 고정된 제작 단계가 아니다. 시각·소리·의미·관람 경험 중 어느 곳에서도 시작하거나 되돌아갈 수 있다. 구현·렌더링으로 자동 전환하지 않는다. 이후 사용자 U006이 10초 코드 샘플을 명시적으로 요청했으므로 이번 샘플은 구현·렌더링하며, 컨셉과 결정의 기록은 계속 문서로 유지한다.

## 의견과 발견의 기록

기록에는 날짜, 관련 제안, 사용자 원문, 에이전트 해석, 결정 상태와 이유를 구분해 남긴다. 이유가 제시되지 않았으면 추정하지 않고 ‘미제공’으로 쓴다. 감상하지 않은 출력물에 평가를 만들어 붙이지 않는다.

‘더 평온하다’는 의견이 나와도 ‘멜라토닌이 증가했다’로 바꾸지 않는다. 반대로 생리학적 효능이 입증되지 않았다는 이유로 감각적 의미까지 폐기하지 않는다.

아름다움을 합산 점수로 결정하지 않는다. 어떤 관계가 새로 보였는지, 무엇에 오래 머물고 싶었는지, 어떤 불편이나 낯섦이 의미 있었는지를 대화로 구체화한다. 한 번 선택한 안도 완결된 정답이 아니라 현재의 선택이다.

## 출력 언어의 경계

연구와 협업 지시문은 제작 문서에 남긴다. 시각·음향 제안에는 빛의 결, 운동, 공간, 소리와의 관계 등 감각적 내용만 전달한다. 뇌과학 용어·의학 도식·명령문을 작품 화면에 옮기지 않는다.
